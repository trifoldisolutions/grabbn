================================================================================
  GRABBN — ADMIN PANEL BUILD PLAN
================================================================================
Last updated: 2026-04-11

OVERVIEW
--------
Build a full admin panel for the Grabbn platform, accessible at /admin/* and
backed by protected API routes at /api/admin/*. Two admin tiers are supported:
  - moderator    : content moderation, user management (limited)
  - superadmin   : full access including financial, system, and partner controls

================================================================================
  PHASE 1 — FOUNDATION
================================================================================

[ ] 1.1  User Model — Add Admin Role Field
    File : server/models/user.js
    Task : Add role field to the User schema:
             role: {
               type: String,
               enum: ['user', 'moderator', 'superadmin'],
               default: 'user'
             }
    Note : First superadmin must be set manually in the database.

[ ] 1.2  Admin Auth Middleware
    File : server/middleware/adminAuth.js  (new file)
    Task : Export two middleware functions:
             requireModerator(req, res, next)
               → allows moderator + superadmin
             requireSuperadmin(req, res, next)
               → allows superadmin only
    Note : Both must be stacked after anonymousAuth (which populates req.user).
           Return 403 if role check fails.

[ ] 1.3  Admin Router — Bootstrap
    File : server/routes/admin.js  (new file)
    Task : Create the root admin router.
           Apply anonymousAuth + requireModerator to all routes via router.use().
           Sub-routers (users, reports, buckets, etc.) will be mounted here.

[ ] 1.4  Mount Admin Router in serve.js
    File : serve.js
    Task : Import and mount:
             app.use('/api/admin', adminRouter);
           Place it after standard API route mounts.

[ ] 1.5  Admin UI — Base Layout & Entry Point
    Files: views/admin/layout.ejs  (new)
           views/admin/login.ejs   (new, if admin login is separate)
    Task : Create a base EJS layout for the admin panel:
           - Sidebar navigation (links to each section)
           - Top bar (logged-in admin name, role badge, logout)
           - Content area slot
           - Tailwind-based, dark or neutral theme distinct from the main app
    Note : Admin UI is served at /admin/* by Express directly (not a SPA).
           Add app.get('/admin', requireModerator, ...) page routes in serve.js
           or a dedicated views router.

  PHASE 2 — USER MANAGEMENT
================================================================================

[ ] 2.1  API Routes — /api/admin/users
    File : server/routes/admin/users.js  (new)
    Routes:
      GET    /api/admin/users
               → list users with pagination + filters:
                 email, username, role, isEmailVerified, isPartner, flagged,
                 accountSuspendedAt (suspended), createdAt range, country
      GET    /api/admin/users/:userId
               → full user detail (buckets count, credits, partner status,
                 transaction count, reports made against them, join date, geo)
      PATCH  /api/admin/users/:userId/role
               → change role (moderator ↔ user; superadmin only for promotions)
               Tier: superadmin only
      PATCH  /api/admin/users/:userId/suspend
               → suspend or unsuspend account (toggle accountSuspendedAt)
               Tier: moderator+
      PATCH  /api/admin/users/:userId/verify
               → force-mark email as verified
               Tier: moderator+
      PATCH  /api/admin/users/:userId/partner
               → grant or revoke isPartner flag
               Tier: superadmin only
      PATCH  /api/admin/users/:userId/credits
               → add or subtract credits (with a reason string for audit)
               Tier: superadmin only
      DELETE /api/admin/users/:userId
               → hard-delete user immediately (bypass 70-hour window)
               Tier: superadmin only

[ ] 2.2  UI Page — /admin/users
    File : views/admin/users.ejs  (new)
    Task : Table of users with:
           - Search bar (email / username)
           - Filter dropdowns (role, status, partner)
           - Sortable columns (joined, credits, country)
           - Pagination
           - Row actions: View, Suspend, Verify, Delete (role-gated in UI too)
    File : views/admin/user-detail.ejs  (new)
    Task : Single user view with:
           - Profile summary card (email, username, role badge, join date, geo)
           - Stats (buckets, comments, credits, transactions)
           - Action buttons (suspend, verify, adjust credits, change role)
           - Recent activity log (last 10 buckets, last 5 reports against them)

  PHASE 3 — CONTENT MODERATION

[ ] 3.1  Report Model — Review Status Field
    File : server/models/report.js  (check if exists, may need new file)
    Task : Ensure the Report document has:
             status: { type: String, enum: ['pending', 'reviewed', 'actioned'], default: 'pending' }
             reviewedBy: { type: ObjectId, ref: 'User' }
             reviewedAt: Date
             action: String  (e.g. 'dismissed', 'content_removed', 'user_banned')
    Note : If Report model doesn't exist yet as a separate collection, create it.
           Buckets and comments currently embed report data — evaluate whether to
           migrate or keep inline.

[ ] 3.2  API Routes — /api/admin/reports
    File : server/routes/admin/reports.js  (new)
    Routes:
      GET    /api/admin/reports
               → paginated list of pending reports
                 filter by: type (bucket | comment), status, date range
      GET    /api/admin/reports/:reportId
               → single report detail with full context
                 (reported content, reporter info, reported user info)
      PATCH  /api/admin/reports/:reportId/dismiss
               → mark reviewed, no action taken
               Tier: moderator+
      PATCH  /api/admin/reports/:reportId/remove
               → remove the reported content (delete bucket or comment)
                 mark report as actioned
               Tier: moderator+
      PATCH  /api/admin/reports/:reportId/ban
               → remove content + suspend the reported user
               Tier: moderator+

[ ] 3.3  UI Page — /admin/reports
    File : views/admin/reports.ejs  (new)
    Task : Reports queue UI:
           - Tabs: Pending / Reviewed / All
           - Filter by type (bucket / comment)
           - Each report card shows: reported content preview, reporter,
             reported user, report reason, date
           - Action buttons per card: Dismiss | Remove Content | Remove + Ban
           - After action, card is removed from pending queue (optimistic UI)
