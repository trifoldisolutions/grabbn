1. PROMOTE MY BUCKET (feature)
──────────────────────────────────────────────

WHAT IT IS
  A "Promote this Bucket" button inside the bucket creation/edit modal,
  sitting just below the 3-pill visibility toggle (Public / Unlisted / Private).

PRICING MODEL — decision: Fixed Tiers (deferred)
  - Fixed price: simple to ship, leaves money on the table, no demand adaptation.
  - Adaptive (auction-based): better long-term but adds complexity.
  - CHOSEN DIRECTION: Fixed price tiers (e.g. Basic / Featured / Spotlight).
    Simple to understand, easy to adjust later, still gives flexibility.
  - Full implementation deferred until Partnership Program is live.

ACCESS CONTROL — decision: Partner-only
  - Open (anyone pays): risk of promoting low-quality or harmful buckets.
  - CHOSEN DIRECTION: Partners only. Prevents the platform from amplifying
    bad-values content just because someone paid.
  - Standard users see the button greyed out + "Become a Grabbn Partner" CTA.

CURRENT UI STATUS
  - Button is present in modal (greyed out for non-partners).
  - "Become a Grabbn Partner" link shown below button for standard users only.
  - Button is active/clickable for partners (promotion flow TBD).

2. PLATFORM RAN ADS (feature — built)
──────────────────────────────────────────────

HOW IT WORKS
  - By default, the platform reserves the right to run ads inside all public buckets.
  - Ads look like regular items: title + thumbnail + link.
  - Ads have a distinct border + "Advertisement" badge so users can tell them apart.
  - Toggle is always ON and always visible.

TOGGLE BEHAVIOUR
  - Standard users: toggle is disabled (greyed out). They cannot change it.
    The "Don't run ads in my bucket" link points to /v2/partnership (upgrade CTA).
  - Partner users: toggle is interactive. They can disable/enable ads per bucket.
    Disabling = they opt out of ad revenue for that bucket.
    Enabling = platform runs ads AND the partner earns a revenue share.

OPEN QUESTIONS
  - Even with ads "disabled" by a partner, does the platform still run them
    silently, or are ads truly off? (Trust / contract question.)
  - What is the revenue share %? (Finance/legal question, not a code question.)

3. PARTNERSHIP PROGRAM — PAGES TO BUILD
──────────────────────────────────────────────

A. ABOUT PAGE  (/v2/partnership)
   Must clearly answer:
     - What is the program?
       → Earn from ads in your buckets, control over ad display,
         bucket promotion access, partner badge, future perks.
     - Who is it for?
       → Curators with quality, values-aligned content.
     - What does Grabbn expect from partners?
       → Content quality standards, no harmful/misleading buckets.
     - How does approval work?
       → One-time review; once approved, partners act freely within policy.
     - What happens if a partner violates standards?
       → Partner status can be revoked (needs policy definition).
   Tone: marketing + trustworthy. Should feel like a serious commitment, not
   just a perk page.

B. APPLICATION PAGE  (/v2/partnership/apply)
   Form fields to decide (see open questions below).
   Flow:
     1. User fills out form → submitted → stored in DB.
     2. User can return and see their application status (pending / approved / rejected).
     3. Admin reviews and approves or rejects.
     4. On approval → user.isPartner flips to true (auto or manually triggered).
     5. User is notified of the decision.

   DB WORK NEEDED:
     - New model: PartnerApplication
       Fields: userId, status (pending/approved/rejected), submittedAt,
               reviewedAt, reviewedBy (admin), rejectionReason (optional),
               [application form fields TBD]
     - user.isPartner already added to User model (Boolean, default: false).

4. OPEN QUESTIONS — needs answers before building
──────────────────────────────────────────────

  Q1. ADMIN PANEL
      Does an admin panel already exist, or will applications be reviewed
      directly in the DB for the first version?
      → This determines how much admin-side UI needs to be built.

  Q2. APPLICATION FORM FIELDS
      What do you want to ask applicants?
        Option A: Just a written pitch ("Why do you want to be a partner?")
        Option B: Structured fields — links to best buckets, niche/topic,
                  follower count, social presence, intended use of promotion.
        Option C: Hybrid — short pitch + a few structured fields.

  Q3. PARTNER BADGE
      Should approved partners get a visible badge on their profile and/or
      on their bucket cards? If yes, what does it look like?

  Q4. REVENUE SHARE & PAYOUT
      Is the actual payout/cashout mechanism in scope for v1, or is the
      first version purely about getting the isPartner flag and the
      controls it unlocks (ads toggle, promote button)?
      → Recommendation: defer payout to v2. Ship access controls first.

  Q5. APPROVAL FLOW AUTOMATION
      On admin approval, should isPartner flip automatically via the app,
      or will admins update it manually in the DB for now?

  Q6. PARTNER REVOCATION
      If a partner violates content standards, what is the revocation flow?
      Is there a warning system, or immediate removal?

  Q7. PROMOTE BUTTON — what does it actually do when clicked (for partners)?
      Options:
        - Opens an in-modal sub-panel with tier selection + payment.
        - Navigates to a dedicated /v2/promote/:bucketId page.
        - Opens a separate modal entirely.
